# 歷史導覽不應中止執行中的對話

2026-09-21：使用者回報切換對話出現 `[Request interrupted by user]`。

程式確認：上方分頁切換走 `deactivate()`，忙碌回合繼續背景執行；歷史清單走 `openHistory()`，原本會無條件替換 session，Claude 狀態機因此送出 interrupt。連點目前正在執行的歷史也會觸發。這是確認存在的中止路徑，未將使用者那次事件直接歸因於此（尚無當次操作紀錄）。

修正主程序的歷史導覽：

- 目標就是目前 session：不做替換。
- 同專案、同 provider 的其他分頁已開啟目標：聚焦該分頁。
- 目前回合忙碌且目標尚未開啟：建立同 provider 的歷史分頁，保留 worktree 路徑；原 core 留在背景。
- 非忙碌且目標尚未開啟：保留原本的歷史載入方式。

開啟新歷史分頁的 state 一次提交，並使用不同 thread ID，避免空 thread 和歷史 thread 重複。聚焦時間大於現有分頁時間，避免同毫秒操作無法切換。

驗證：typecheck、正式 build 通過；105 個測試檔、2,252 項測試通過。新增三項 IPC 回歸，驗證同 session 不重開、忙碌時另開歷史且不 dispose 舊 core、目標正在另一分頁執行時直接聚焦。既有 Claude／Codex 背景執行測試一併通過。

本輪未呼叫付費模型做執行中實機重現；測試覆蓋路由與核心生命週期。已確認現有工作台無忙碌／待批准／輸入草稿後重啟，以載入主程序修正。切換前景仍會取消該分頁正在使用的共用瀏覽器工具，避免背景操作目前的瀏覽器；不等於中止整個模型回合。
