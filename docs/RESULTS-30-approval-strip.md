# RESULTS-30:批准卡一眼找得到(真實使用回報)

- 日期:2026-09-15
- 分支:`approval-strip`(codex gpt-6-astra 實作,sonnet 審查)
- 來源:使用者 2026-09-15 第一天真實使用的回報:「批准會在一長串對話中間,我需要一直回滾去找」、「送出訊息沒反應」

## 1. 現況(改之前)

前景對話的批准卡掛在 tool block 原位、在捲動容器裡,後續內容會把它推走;狀態列「待批准」只切專案與分頁,
整個 renderer 沒有 `scrollIntoView` 也沒有 `.focus()`,卡片的 y/n 鍵盤沒人聚焦就按不到;輸入框等批准時只變灰,
不說原因。「送出訊息沒反應」很可能就是這個:agent 收到後要求批准,卡在畫面外。

## 2. 改了什麼

- 輸入框上方固定一條 `PendingStrip`:每個待批准一列「`<工具名>` 在等你批准」加「前往 / 允許 / 拒絕」。卡片不搬,上下文在 tool block 那裡。
- 「前往」與狀態列「待批准」都會把卡 `scrollIntoView({ block: 'center' })` 並 `.focus()`,y/n 直接能用。
- 輸入框等批准時 placeholder:「有 N 個工具在等你批准,先回答上面的卡片」。

## 4. 審查抓到的兩條與重驗

**跳轉會重複觸發。** 跳轉的 effect 依賴整個 `active` 陣列,而它在**任何**對話的批准事件到達或了結時都會換參考,
所以按過一次「待批准」之後,只要還待在那個 pane,不相干的批准也會把畫面捲回去、把焦點搶走。
改成同一個 `jumpToken` 只跳一次(`useRef` 記上次跳過的 token),依賴改成 `active[0]?.requestId`。
重驗:按「前往」跳到卡片後,讓另一個對話產生一次批准事件,再切回來,卡片的 `scrollIntoView` 被呼叫 **0** 次 ✓

**提示條沒有防連點。** 卡片本身有(`answered` state),提示條沒有;主行程對同一個 requestId 只認第一次,
第二次會記一筆「找不到 requestId」的假錯誤。提示條每一列按過就把三顆按鈕 `disabled`。
重驗:間隔 80ms 的兩次點擊,第二次時那一列已經消失、點不到,log 沒有新的假錯誤 ✓
(同一個 tick 內連按兩次仍會送兩次,但那是程式模擬才做得到的操作,真人辦不到;`ApprovalCard` 也是同樣的特性。)

自動測試:1954 全過;Stmts 94.47%、Branch 90.50%。
