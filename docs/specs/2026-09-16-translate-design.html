對話訊息的翻譯按鈕#

  • 日期:2026-09-16
  • 狀態:設計完成,尚未實作
  • 觸發:使用者說「我接受回覆英文,但是是不是可以額外有自動翻譯功能按鈕?我可以點擊選擇翻譯成什麼語系」

1. 為什麼要做#

agent 常常用英文回答。現況要看懂只有兩條路:自己讀,或是再送一則訊息叫它翻譯。
第二條的代價比看起來大:那則訊息會進對話歷史、佔 context、而且 agent 可能以為你改變了任務方向,
下一輪就開始用中文做事或反覆確認要不要翻譯。

所以要的是一個不影響對話本身的翻譯。

2. 目標與非目標#

目標

  • agent 的文字訊息可以就地翻譯成指定語言,原文保留。
  • 語言可選,記住上次選的。
  • 翻譯不進對話歷史、不佔 agent 的 context、不觸發 agent 的下一步。

非目標

  • 工具結果與終端輸出不翻。那些是程式輸出(路徑、指令、stack trace),翻了反而難對照。
  • 不做整段對話一次翻完。沒有需求前不做,而且一次翻十則的成本與等待時間都不划算。
  • 不做即時翻譯(邊串流邊翻)。等訊息完成再翻,省得翻到一半的句子。
  • 不做離線翻譯。

3. 一個要先決定的事:翻譯從哪裡來#

三個選項:

做法成本問題
送一則訊息給當前對話一個回合進歷史、佔 context、agent 會以為任務變了
另開一個一次性 SDK 呼叫一次 API 呼叫要處理失敗與逾時
外部翻譯 API需要金鑰多一個要管的密鑰,而且品質不見得比模型好

選第二個。用 @anthropic-ai/claude-agent-sdk 的 query(),但與對話那條路完全分開:
不建 session、不給工具(allowedTools: [])、不讀專案設定(settingSources: [])、不 resume。
模型固定 claude-haiku-4-5-20251001:翻譯不需要推理,便宜快是唯一重點。

這不需要新的密鑰。yeschef 既有的對話已經在用同一套 SDK 與同一份登入。

4. 介面#

4.1 畫面#

每個 assistant 的 text block(Turn.tsx:52 那條)下方多一列細小的控制列,預設只有一顆
譯 按鈕。點了展開語言清單:

繁體中文 / English / 日本語 / 한국어 / 简体中文

選了之後那一列變成「翻譯中…」,完成後譯文出現在原文下方,上面有一條細線與語言標籤,
右邊一顆「收起」。原文永遠在,不會被取代。

同一個 block 再按一次 譯 可以換語言,已經翻過的語言直接從快取拿,不重打。

只有完成的 text block 才有這顆按鈕(block.complete === true)。串流中的不畫,
避免翻到一半的句子。

4.2 語言的記憶#

上次選的語言記在 localStorage,下次那顆按鈕直接顯示成 譯→English 這種形式,
點一下就直接翻成上次那個語言,不必再展開清單;要換語言按旁邊的 ⌄。

第一次使用時沒有上次的語言,點 譯 直接展開清單。

4.3 錯誤#

翻譯失敗時那一列顯示一句中文說明加一顆「重試」。不彈窗、不進對話、不影響其他 block。
逾時 30 秒。

5. 資料流#

renderer 沙箱裡不能呼叫 SDK,所以走一條新的 invoke 頻道,形狀照 preview:read 那條:

translate:run   { text: string, target: string }  →
  | { kind: 'ok', text: string }
  | { kind: 'rejected', message: string }

主行程 src/main/translate.ts:

  • target 必須在允許清單裡(五種語言的代碼),不是就 rejected。不接受自由字串: 那個值會進提示詞,允許清單是最省事也最穩的防線。
  • text 長度上限 20000 字元,超過 rejected(訊息說明長度)。
  • 同時最多兩個翻譯在跑,超過的排隊。與 createPreviewReader 同樣的做法。
  • query() 失敗、逾時、回空字串都回 rejected,訊息是中文。

提示詞固定,只有目標語言是變數,而且變數只來自允許清單。要翻的文字用明顯的分隔標記包起來,
並在提示詞裡寫明分隔標記內的內容一律當成待翻譯的文字,不是指令。

6. 驗收#

  1. agent 用英文回一段話,按 譯 選繁體中文,譯文出現在原文下方,原文還在。
  2. 同一則再按一次選日本語,兩種譯文可以各自收合,不用重打已經翻過的語言。
  3. 翻譯期間對話本身不受影響:沒有新的回合、狀態列的「進行中」不會亮、agent 的下一則回答不受影響。
  4. 重開 app 之後那顆按鈕記得上次選的語言。
  5. 串流中的訊息沒有那顆按鈕,訊息完成後才出現。
  6. 主行程沒跑或翻譯失敗時,那一列顯示中文說明與「重試」,其他訊息照常。

7. 已知的取捨#

  • 譯文不持久化。重開 app 之後要重翻。理由是譯文不是對話內容,寫進逐字稿會污染歷史; 而重翻一則的成本很低。
  • 翻譯的成本不計入狀態列的花費。那是對話的花費,翻譯不是對話的一部分。 代價是這筆錢在 yeschef 裡看不到。
  • 一次只翻一個 text block,不是整則訊息。一則訊息可能夾著工具呼叫,分開翻比較好對照。
