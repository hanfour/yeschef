# YesChef UI 優化驗收 — 2026-09-21

本次涵蓋工作台、對話、歷史、終端機、文件預覽、Skills 與協作卡片。已將正式建置載入正在使用的 YesChef，並以真實工作台驗收。

| Before | After | Why |
| --- | --- | --- |
| 控制項、卡片、文件色彩各自定義 | 共用暗色主題、語意狀態色與 SVG 圖示 | 讓主要操作與狀態一致可辨 |
| 大量等寬文字、角色欄占用橫向空間 | 一般文字使用 sans，程式碼保留 monospace，角色置於訊息上方 | 增加對話與文件的可讀範圍 |
| 歷史固定占空間且無搜尋 | 可收合、依標題／摘要／分支／路徑搜尋，窄欄使用抽屜 | 快速找回工作並保留對話空間 |
| 空白對話缺乏引導、輸入框固定高度 | 空狀態引導、72–220px 自動增高、空白送出停用 | 提供清楚起點與多行編輯體驗 |
| 窄視窗擠入左右欄 | 900px 以下切換對話／預覽，700px 以下的對話欄使用歷史抽屜 | 文件與對話各自保有完整閱讀空間 |
| 多分頁時目前分頁可能在畫面外 | 自動水平顯示選中分頁；方向鍵、Home、End 可切換 | 提升鍵盤操作與定位能力 |
| 批准、交接、錯誤缺乏一致層級 | 琥珀色批准、藍色交接、暖紅色錯誤；工具內容可捲動 | 讓需要處理的事項清楚可見 |

## 真實工作台驗收

以 Electron 正式 renderer 執行，使用現有 demo-app／chat-bot 專案：

- 搜尋歷史、收合後保留草稿、15 行輸入增高至 220px 並可捲動。
- 鍵盤切換專案、開啟及關閉 zsh 終端機、開啟 Skills 共用庫。
- 480×820 CSS viewport：無水平溢位、目前分頁可見、歷史抽屜能以 Escape 關閉。
- 從對話點擊範例文件，切換到完整文件預覽並定位來源行。
- 回到桌面後預覽欄恢復原本 800px。
- 檢查無草稿／執行中 agent 後才重新載入新版；驗收未送出模型工作。

截圖捕捉窄版時改用 CDP `Page.captureScreenshot`，避免 Playwright 在 Electron 擷取時改變模擬 viewport。桌面為實際 Electron 畫面，窄版為同一 renderer 的 viewport 模擬，未做實體觸控裝置驗收。
