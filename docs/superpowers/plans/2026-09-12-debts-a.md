### Task 2: 歷史檢視看得到花費

**Files:**
- Modify: `src/shared/projects.ts:27-36`(`SessionLink` 加選填 `cost`)
- Modify: `src/main/projects-state.ts`(加 `recordSessionCost`)

- Modify: `src/main/session-store.ts:129-142`(`loadHistory` 接一個 `costOf(sessionId)`)
- Test: `tests/projects-state.test.ts`(加)、`tests/session-store.test.ts`(加)、`tests/ipc-bridge.test.ts`(加)

現況:live 的 `session-end` 有 `costUsd`/`numTurns`(來自 SDK 的 `result` 訊息),但逐字稿裡沒有 `result` 行(實際掃過 `~/.claude/projects/*/*.jsonl`,0 次),所以歷史載入時 `session-store.ts:139` 補的 `session-end` 沒有花費,`fold.ts:244` 的 `sessionEndCost` 回 undefined,狀態列與對話底部都不畫。

設計:花費存進狀態檔裡該 session 的 `SessionLink`(每個 session 本來就有一筆),歷史載入時查回來。codex 的 `session-end` 有 `tokens`,一樣存。

**Interfaces:**
- `SessionLink.cost?: { readonly usd?: number; readonly turns?: number; readonly tokens?: number }`(形狀跟 `fold.ts:14` 的 `cost` 一樣,直接 import 那個型別或抽成共用)。
- `recordSessionCost(state, projectId, sessionId, cost): ProjectsState`:找到任一 thread 裡 `sessionId` 相符的 link 就設 `cost`;找不到回原 state。
- `sessionCostOf(state, sessionId): SessionLink['cost']`。
- `loadHistory` 補的 `session-end` 帶上 `costOf(sessionId)` 回傳的三個欄位(有的才帶,跟 live 一樣的條件展開)。

- [ ] Step 1:三個測試檔各加:`recordSessionCost` 找得到就設、找不到不動、原 state 不變;`loadHistory` 在 `costOf` 有回傳時 `session-end` 帶 `costUsd`/`numTurns`、沒有時不帶;ipc-bridge 收到帶花費的 `session-end` 後狀態檔的 link 多了 `cost`。ipc-bridge 的測試沿用檔案裡的既有 helper。
- [ ] Step 2:確認失敗。
- [ ] Step 3:實作。ipc-bridge 攔 `session-end` 的位置:找 `sink` 裡處理事件批次的地方,或 `onEnded`;哪裡拿得到 `costUsd`/`numTurns`/`tokens` 與當下的 sessionId 就在哪裡呼叫 `service.update((s) => recordSessionCost(...))`。只在三者至少一個有值時寫,避免每次結束都改狀態檔。
- [ ] Step 4:全綠、coverage、build。
- [ ] Step 5:`git commit -m "feat: 對話花費存進狀態檔,歷史檢視也看得到"`

### Task 3: 狀態檔裡的每個對話都登錄成同伴

**Files:**
- Modify: `src/main/ipc-bridge.ts:245-287`(`registerPeer`)與 `:352-370`(projects 訂閱)
- Test: `tests/ipc-bridge.test.ts`(加)、`tests/peer-registry.test.ts`(視需要)

現況:`registerPeer` 在 `createSlot` 裡,slot 只在對話被切成前景時懶建,所以這次開機沒被切到的對話(其他專案的、同專案非前景的)不在 `registry` 裡,`ask_peer` 找不到它們。RESULTS-14 §3 記「三個對話要各自跑過一輪才會互相看得見」。

設計:登錄不等 slot。bridge 建立時與每次 projects 狀態變動時,對每個 `contentType === 'conversation'` 的分頁確認登錄一次(已登錄的跳過,分頁被關掉的解除)。登錄的 `isBusy` 在沒有 slot 時回 false;`deliver` 在沒有 slot 時先 `slotFor(conversationId)` 建出來再 `core.userInput(text)`。`linkId` 照現在從狀態檔的 thread 取,所以從來沒跑過的對話仍會被 `alive()` 過濾掉,這是對的:沒有 sessionId 就沒有可以被問的對象。

注意:`slotFor` 建出來的核心在背景,`core.userInput` 對非前景核心要能運作(5a 第一階段修過 sleep 與注入的競態,`conversation.ts` 的 `userInput` 有 retry 一次的邏輯);測試要涵蓋「對沒有 slot 的對話 deliver,會建 slot 並把文字送進去」。

- [ ] Step 1:ipc-bridge 測試加:狀態檔兩個專案各兩個對話、只有一個被切成前景 → `registry` 有四筆;對非前景那筆呼叫 `deliver` → slot 被建、假 core 收到 `userInput`;關掉一個分頁 → 該筆解除。
- [ ] Step 2:確認失敗。
- [ ] Step 3:實作。`registerPeer` 從 `createSlot` 搬出來,改成 `ensurePeerRegistered(conversationId, projectId)`;`createSlot` 不再登錄(已登錄的話 registry 的 `register` 要能冪等,看 `peer/registry.ts` 現況決定是覆寫還是跳過)。
- [ ] Step 4:全綠、coverage、build。
- [ ] Step 5:`git commit -m "fix: 狀態檔裡的每個對話都登錄成同伴,不必先切到前景"`
