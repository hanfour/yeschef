# RESULTS-33:對話訊息的翻譯按鈕

- 日期:2026-09-16
- 分支:`translate`,九個 commit
- 規格:`docs/specs/2026-09-16-translate-design.md`
- 起因:使用者說「我接受回覆英文,但是是不是可以額外有自動翻譯功能按鈕?我可以點擊選擇翻譯成什麼語系」

## 做了什麼

agent 的每則文字訊息下方一顆按鈕,點了選語言(繁體中文、English、日本語、한국어、简体中文),
譯文出現在原文下方,原文保留。記住上次選的語言,下次直接顯示成「譯→English」一鍵翻譯。
同一則可以翻多種語言並存,各自收合,翻過的不重打。

翻譯走一條與對話完全分開的一次性 SDK 呼叫:不寫 session 檔、不給工具、限一回合、
不讀專案設定、不 resume,模型固定 Haiku 4.5。所以翻譯不進對話歷史、不佔 agent 的 context、
不會讓狀態列的「進行中」亮起來。

## 六項實機驗收

| # | 情境 | 結果 |
|---|---|---|
| 1 | 按譯選繁體中文 | 譯文在原文下方、原文還在、`aria-expanded`/`aria-controls` 都在、五種語言逐字相符 |
| 2 | 同一則再選日本語 | 兩種譯文並存、各自可收起、收起一個剩一個 |
| 3 | 翻譯的 6 秒期間 | 沒有「進行中」、狀態列沒亮、turns 沒變多 |
| 4 | 重開 app | 按鈕仍是「譯→日本語」,`localStorage` 是 `ja` |
| 5 | 串流期間 | 翻譯列數恆為 0,訊息完成後才出現 |
| 6 | 失敗 | 「同時翻譯的請求太多,請稍後再試」+ 重試,`role=alert`,既有譯文不受影響;按重試真的再打一次並成功 |

另外量到快取是有效的:第一次翻譯 5.3 秒,收起後再按同一語言 0.1 秒且沒有出現「翻譯中」。

## 五輪審查各自擋下的東西

單元測試一路全綠,底下每一項都是審查或實機才發現的。

**兩個 blocker 都是規格寫錯造成的。**

`allowedTools: []` 不是「不給工具」。SDK 宣告寫的是「List of tool names that are
**auto-allowed without prompting**… To restrict which tools are available, use the `tools` option instead」。
`tools: []` 才是 Disable all built-in tools。所以 Bash/Read/Write 一直都在那個 haiku 的 context 裡;
加上沒有 `maxTurns`,注入成功的文字可以讓它繞好幾輪工具撐到逾時,而 adapter 把所有 assistant 訊息
串起來當譯文。改成 `tools: []` 加 `maxTurns: 1`。

`persistSession` 預設 true。翻譯的 session 會寫進 `~/.claude/projects/`,而且沒設 `cwd` 就用
`process.cwd()`,於是那些翻譯變成標題是「把下面 `<<<SOURCE-…>>>` 與…」的對話出現在 Recents 裡、
點得下去、resume 得了。規格 §2 寫的是「翻譯不進對話歷史」。
這不是理論:`grep -rl "<<<SOURCE-" ~/.claude/projects/` 當場撿到 10 個驗收留下的檔案。
改成 `persistSession: false` 並顯式給一個與任何專案無關的空目錄。

**固定的分隔標記可以被翻譯的內容偽造。** 待翻譯的文字是 agent 的輸出,不受信任。
審查者把偽造後的 prompt 印出來:原文裡塞一個 `<<<END>>>`,後面的指令在結構上就落到「標記外」。
改成每次請求隨機產生的 nonce。沒有改成「含標記就拒絕」,那會讓「討論這個功能本身」的訊息永遠翻不了。

**`translate` 這個 export 的限流形同虛設。** 它每次呼叫都建一個 `inFlight` 從 0 開始的新限流器。
審查者實測 5 個並發呼叫,5 次全部放行。當時沒有人用它,但那個名字最像「就是拿來翻譯的那個函式」,
下一個接手的人會誤用而且不會有任何錯誤提示。整個刪掉,`createTranslator` 是唯一的對外 API。

**逾時之後名額提早釋放。** 名額原本綁在 race 結束,所以逾時一回覆就放掉,底層 `query` 還在跑。
審查者實測讓兩個「永遠掛著」的請求同時存在。改成綁底層 promise 真的 settle,
並在 abort 之後給一段寬限期,逾期仍未結束就記一次錯誤,免得名額卡死時訊息騙人
(說「太多」其實是壞了)。

**使用者自己打的訊息下面也有翻譯按鈕。** 實機才看得出來:`renderBlock` 的 `case 'text'`
對 user turn 一樣會走到,而測試測的是 block 不是 turn,所以全綠。改成 `RenderOptions` 帶 `role`。

**第一次使用時「譯」那顆按鈕沒有 `aria-expanded`。** 那兩個屬性原本只加在「⌄」上,
而「⌄」要翻過至少一次才出現,等於最常見的路徑沒有。

**有邏輯的東西寫進了被覆蓋率排除的檔案。** `vitest.config.ts` 排除 `src/main/index.ts`,
理由是「Electron 啟動接線,無測試縫」。這次把 abort 轉發、SDK 訊息的過濾串接、來源檢查都寫了進去,
審查者實測刪掉來源檢查那整行,2172 則測試全綠。抽成 `src/main/translate-query.ts`。

## 安全

- `translate:run` 能拿到模型呼叫,所以 handler 有一道來源檢查,只接受左側 renderer。
  右窗格那個跑任意網頁的 view 本來就沒有 preload,打不到這條;來源檢查是第二層。
- 目標語言只接受五個代碼的允許清單,不接受自由字串。顯示名稱只從清單取,不讓 renderer 的字串進提示詞。
  `isTranslateLanguage` 用 `.some()` 加 `===` 純值比較,`'constructor'`、`'__proto__'` 這類原型鏈上的 key 擋得住。
- 譯文走既有的 `Markdown` 元件,那個元件沒有 `rehype-raw`、沒有 `dangerouslySetInnerHTML`,
  模型輸出的 HTML 只會被跳脫成文字。
- 工作目錄是一個專屬的空目錄,不是 userData 本身(那裡有 Cookies 與專案狀態檔)。
  今天工具是關的所以碰不到,但「agent 的工作目錄」不該預設就是 app 自己的狀態區。

## 已知的取捨

- 譯文不持久化,重開 app 要重翻。譯文不是對話內容,寫進逐字稿會污染歷史。
- 翻譯的花費不計入狀態列。那是對話的花費,翻譯不是對話的一部分。代價是這筆錢在 yeschef 裡看不到。
- 上次選的語言只在每個控制列第一次出現時讀一次,同視窗其他訊息不會即時跟著變。
- 譯文還沒回來就切到別的對話時,那次翻譯不會被取消,結果直接丟掉。
- 工具結果與終端輸出不翻。那些是程式輸出,翻了反而難對照。

## 上線後第一個回報:正常長度的訊息必定逾時

使用者實際用了兩次,兩次都是「翻譯逾時,請稍後再試」。

主行程的 log 裡是兩筆 `Claude Code process aborted by user`,也就是我們自己的 30 秒逾時在中止。
用同一組 options 直接跑真的 SDK,短句子 5.9 秒,機制沒問題,所以問題出在長度。

量測過程中有一次假的結論值得記下來。第一版的長文素材是同一段重複 8 次,量到「關掉延伸思考快 4 倍」,
但那是因為模型把重複的段落合併掉了,輸出從 1135 字掉到 136 字 —— 快的是輸出變少,不是變快。
換成不重複的 4421 字元英文,各跑兩次:

| | 第 1 次 | 第 2 次 |
|---|---|---|
| 思考開著(原本) | 43.0 秒 | 26.2 秒 |
| 思考關掉 | 15.0 秒 | 22.4 秒 |

同一組設定兩次差 43 秒與 26 秒,所以「快 2.9 倍」不可靠。穩的結論只有一個:
兩種設定都會逼近或超過 30 秒,真正的錯是逾時設太短。

三件一起改:逾時 30 秒改成 180 秒(照量到的速率推到 20000 字元的上限約需 100 秒,留了餘裕)、
關掉延伸思考(翻譯不需要推理,附帶省 token)、翻譯中顯示已經等了幾秒,免得看起來像壞掉。
測試裡寫死的 `30000` 改成引用常數。

實機複驗:3374 字元的訊息 19.5 秒翻完,畫面上「翻譯中 0 秒 → 10 秒 → 19 秒」。

## 一則事故

清理驗收留下的 session 檔時,我用 `grep -rl <提示詞片段>` 接 `rm`,
把這個工作階段自己的逐字稿與一個審查 subagent 的 transcript 一起刪掉了,
因為它們「談論」那段文字。`~/.Trash` 與 `~/.claude/backups` 都沒有副本。
程式碼與決策紀錄都在 git 與 ledger 裡,沒有遺失,失去的是回頭翻對話原文的能力。

教訓:「含有這段文字的檔案」與「由這段文字產生的檔案」是兩回事。
`rm` 接在 `grep -rl` 的結果後面之前,必須先把清單列出來看過。
